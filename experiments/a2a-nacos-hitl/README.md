# Unmodified framework baseline: local nested approval vs Nacos A2A approval

Framework baseline: `17e26ff6fe951d605771c1845229ca3edb043634` (`1.1.2.2`).
Derived from the previously delivered `a2a-hitl-repro` source, retaining its deterministic
ChatModel, customer/order tool callbacks, human approval hook, passive graph/A2A audit,
and raw business HTTP write counting. Framework sources are not patched.

## Build and launch

Use JDK 17 and Maven; `./build-baseline.sh` installs the required framework modules into
`/Users/cckowin/test/spring-ai-alibaba-lab/m2` and builds this application. Build logs,
Nacos client logs/cache and runtime evidence reside under that lab directory.

1. Start the real loopback Nacos 3.1.2 server (8848 HTTP / 9848 gRPC, console 18880).
   The administrator must initialize their own credentials. Supply client credentials via
   `NACOS_USERNAME` and `NACOS_PASSWORD`, or an external properties file named in `LAB_CONFIG`.
2. Run `./run-baseline.sh remote` on loopback 18081. Wait for the framework log
   `Auto register agent server_business into Registry Nacos[127.0.0.1:8848] successfully.`
   `AgentRegistryService` registers on ApplicationReadyEvent; this process must be ready first.
3. Run `./run-baseline.sh client` on loopback 18080. Building its A2aRemoteAgent immediately
   resolves `server_business` through the auto-configured NacosAgentCardProvider.
4. Open `http://127.0.0.1:18080/chatui/`. The only exposed agents are `local_sequential`
   and `a2a_sequential`. Use unique inputs such as `create order case=local_approve_01`.
   The common deterministic business model first calls `read_customer`, then requests
   `create_order` approval. `read only case=local_read_01` is a read-only control.

The local graph is SequentialAgent -> ReactAgent. The remote graph is SequentialAgent ->
A2aRemoteAgent -> HTTP -> ReactAgent. Both parents and business agents have MemorySaver.
The business HTTP API is centralized at the client process (18080), so read/write counts
for both paths are in `http://127.0.0.1:18080/repro/status`; remote startup itself does not
call that API. Audit is at `/repro/audit` and in `lab/evidence/baseline/{client,remote}/runtime.jsonl`.
Every `POST /business/orders` increments writes and generates a new order ID, without deduplication.

## Configuration and audit boundaries

Remote AgentCard is generated by A2aServerAgentCardAutoConfiguration using 127.0.0.1:18081.
NacosA2aRegistryAutoConfiguration and A2aServerRegistryAutoConfiguration remain enabled.
Client enables NacosA2aDiscoveryAutoConfiguration and excludes Nacos registry auto configuration
(the upstream registry condition uses a leading-dot property name). It never supplies a fixed card or URL fallback.
A2aServerProperties is explicitly bound because application-owned passive audit router replaces
only the server HTTP handler/router auto configuration. The router uses original GraphAgentExecutor,
original JSONRPCHandler and original JsonRpcA2aRequestHandler. ObservedAgent forwards the exact original
NodeOutput objects unchanged and writes passive JSON audit only. No HITL conversion/resume patch is present.

Read-only audit/status endpoints and the local deterministic model are experiment instrumentation,
not replacements for A2A transport, Nacos discovery, checkpointing, hook logic or native Studio approval UI.

## Fresh HTTP baseline results

Run `python3 test_baseline.py` after both processes are ready. Each invocation uses unique case IDs
and saves raw requests, SSE and independent client/remote audit snapshots under
`/Users/cckowin/test/spring-ai-alibaba-lab/evidence/baseline/http`.

The first actual run, `nacos-baseline-dda43ba8`, observed:

- Local nested approval: before decision reads=1/writes=0; approve writes=1; repeated resume stays 1.
- Local nested rejection: reads=1/writes=0 after rejection.
- Nacos discovered A2A read-only control: reads=1/writes=0 with returned result.
- A2A write: one actual remote InterruptionMetadata, zero Studio approval cards, wire states
  submitted/submitted/completed, reads=1/writes=0. Parent resume using that real remote feedback
  sent no second remote request and writes stayed 0.

Nacos auto registration and discovery succeeded using normal SDK operations without supplied
client credentials. The application task did not change authentication configuration or read any
administrator credentials. Processes remain available for separate browser acceptance.

`../..` tracked and staged diffs were empty after the run. `lab/evidence/baseline/build-provenance.json`
records the HEAD and verifies that all four framework jars embedded in the executable application
match the jars built from local unmodified source byte for byte. Native UI browser verification is
separate; framework unit tests were skipped. No feature bridge patch is present.
